## Per-app knowledge base → site search → optional FAQ chat

**Status:** Deferred — do not build the AI chat until we have real user “How do I…?” volume and enough step-by-step articles. Knowledge-base-first.

**Locked ladder (2026-08-04):**
1. **Capture** — Log every “How do I…?” from `support@`, App Store / Play reviews, in-app feedback, and Meta comments into one place (even a simple sheet).
2. **Knowledge base** — Short **task cards** for repeats only: goal → preconditions → numbered steps → what success looks like. Not “about the app” brochure copy. One set per app (HHH / PBJ / CVC / PAL) living on josspatech.com.
3. **Site search** — Cheap, predictable search over those articles (no LLM required).
4. **Optional AI later** — Per-app “Ask about …” chat only when the KB has enough verified how-tos that answers can stay **docs-only** (no guessing). Follow-ups OK once the corpus is solid. Rate-limit / abuse controls required.

**Why wait:** Current user manuals are often feature/overview-oriented, not step-by-step job cards. An FAQ chat on thin how-tos would invent or vague-answer. Better to learn real questions from users first.

**Notes when ready:**
- Start with the app that gets the most support/ad traffic (likely PBJ or HHH).
- Reuse cards in manuals later; don’t reverse that order.
- Cost: KB + search ≈ free on GitHub Pages; LLM chat ≈ small pay-per-use + worker — only after step 4 is justified.
